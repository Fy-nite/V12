# Skeletal animation (`V12.Skeletal`)

V12 does not implement skeletal animation itself. The `V12.Skeletal` module
wraps a runtime behind an interface, imports models into a backend-neutral asset,
and exposes components for gameplay.

For static geometry, use `ModelInstance`/`MeshAsset` instead — see
[`MODEL_LOADING.md`](MODEL_LOADING.md). This document covers the animated path.

```
V12.Skeletal
├─ Components
│   SkeletalManagerComponent      rig, asset, clips, animator, parts
│   SkeletalPlayerComponent       clip / time / speed / loop / pause
│   SkeletalBoneAttachmentComponent
│   SkeletalMeshPartComponent     generated renderable per submesh
├─ ISkeletalAnimator / ISkeletalBackend
│   └─ ProwlMotionAnimator        default backend ("prowl")
└─ ISkeletalAssetImporter
    └─ ClaySkeletalImporter       default importer ("clay")
```

`Prowl.Motion` evaluates skeletons and clips; `Prowl.Clay` imports
glTF/GLB/VRM/OBJ/FBX. Both are MIT, pure C#, and sit entirely behind the
interfaces above.

## Quick start

```csharp
var character = new Element("Character");
character.SetPosition(0f, 0f, 0f);

character.AddComponent(new SkeletalManagerComponent
{
    AssetPath = "v12://Assets/CesiumMan.glb",
    SampleRate = 30f,
});

character.AddComponent(new SkeletalPlayerComponent
{
    PlayOnLoad = "Walk",   // empty leaves the manager's auto-play alone
    LoopOnLoad = true,
    Speed = 1f,
});

world.AddElement(character);
```

The manager imports the model, builds parts and creates one child element per
material. The children are non-persistent, so only the asset path and playback
settings are saved.

## Playback and seeking

`SkeletalPlayerComponent` owns per-character playback state and forwards to the
manager. Seeking is a first-class time set:

```csharp
player.Play("Run", loop: true, blendTime: 0.25f);
player.CrossFade("Walk", 0.4f);

player.Time = 0.75f;      // seek to 0.75 s in the current clip
float length = player.Duration;
player.Speed = 0.5f;      // slow motion
player.Pause();
player.Resume();
player.Restart();         // seek to 0
```

`player.Time` reads the live cursor, so a scrubber or replay system can use it
directly. The manager exposes the same operations for code that does not need a
player component, plus `GetBoneModelMatrix(index)` for attachments and probes.

`Time` assignment samples the pose immediately, which is what makes scrubbing
and deterministic replays work: the backend has no hidden cursor that only
advances on `Update`.

## Components

### `SkeletalManagerComponent`

| Member | Purpose |
| --- | --- |
| `AssetPath` | `v12://`, `res://`, or a filesystem path. Rebuilds on change. |
| `Importer` / `Backend` | Names in the importer/backend registries. Null picks the default. |
| `SampleRate` | Clip resampling rate used at import time. |
| `PlayOnLoad`, `LoopOnLoad`, `AutoPlay` | Initial clip behavior. |
| `Clips`, `CurrentClip`, `Duration` | Read-only playback info. |
| `Play`, `CrossFade`, `Seek`, `Pause`, `Resume` | Direct control. |
| `Time`, `Speed`, `Loop`, `IsPlaying` | Playback state. |
| `LocalPose`, `BoneLocals`, `BoneParents`, `InverseBindPoses` | Pose for renderers and gameplay. |
| `BoundsMin`, `BoundsMax`, `Height`, `GroundOffset` | Skinned reference-pose bounds. |
| `IndexOfBone(name)`, `GetBoneModelMatrix(index)` | Bone lookup and model-space pose. |

### `SkeletalPlayerComponent`

Owns `PlayOnLoad`, `LoopOnLoad`, `Speed`, and the live `Time` / `Duration` /
`CurrentClip` / `IsPlaying` view. It resolves its manager on the same element,
then the parent, then a child, then the world, and can also be assigned
explicitly.

### `SkeletalBoneAttachmentComponent`

Follows a named bone and converts its model transform into the element's parent
space. Use it for weapons, hats, camera mounts and props:

```csharp
var sword = new Element("Sword");
sword.AddComponent(new SkeletalBoneAttachmentComponent
{
    Manager = character.GetComponent<SkeletalManagerComponent>(),
    Bone = "hand_r",
    Offset = new Vector3(0f, 0.1f, 0f),
});
character.AddChild(sword);
```

### `SkeletalMeshPartComponent`

Generated by the manager, one per material. It exposes the submesh's geometry,
weights and bone indices through `ISkinnedMeshRenderable`, and reads the shared
skeleton from the manager. You normally never create it by hand.

## Swapping the runtime or importer

Both are registries keyed by name:

```csharp
SkeletalBackends.Register(new MyBackend());     // ISkeletalBackend
SkeletalImporters.Register(new MyImporter());   // ISkeletalAssetImporter

manager.Backend = "my";
manager.Importer = "my";
```

`ISkeletalBackend.Create(SkeletonAsset)` returns an `ISkeletalAnimator`. The
animator interface is deliberately small: `LocalPose`, `Clips`, `CurrentClip`,
`Time`, `Duration`, `Speed`, `Loop`, `IsPlaying`, `Play`, `CrossFade`, `Seek`,
`Pause`, `Resume`, `Update`. A backend that cannot cross-fade can implement it
as an immediate switch; a backend that cannot seek can clamp.

The default `"prowl"` backend converts the neutral clip frames to
`Prowl.Motion.AnimationClip` once, then samples them itself so seeking, pausing
and blending are explicit.

## Asset model

`SkeletonAsset` is importer/backend neutral:

- bone names, parent indices;
- reference parent-space transforms and inverse bind poses;
- `SkeletalClipData` clips, stored as uniformly sampled `BoneLocal`
  (position/rotation/scale) frames;
- skinned mesh parts (positions, UVs, normals, tangents, indices, four weights
  and four bone indices per vertex, material);
- reference-pose skinned bounds and import warnings.

Because clips are neutral frames rather than a library type, another backend can
consume the same asset without re-importing.

## Import details

- The model's largest skin is the primary skeleton; bone order is the skin's
  joint order, so vertex bone indices need no remap.
- Non-joint ancestors (a glTF `Armature`, pivot groups) are folded into each
  bone's local transform. Dropping them leaves the mesh in raw mesh space and
  the character lies sideways.
- Sampled node TRS is composed with the **ancestor chain only**, so the node's
  own transform is not applied twice.
- Weights are normalized at import; the renderer and bounds pass agree.
- Curves are resampled at `SampleRate` (30 Hz by default) because Motion's clip
  format is uniformly sampled.
- Embedded textures are written once to a content-hashed temp cache.

## Limitations

- **One skin per asset.** A model with several skinned meshes in different bind
  spaces needs a skin per part; the importer currently takes the largest skin.
- **8-bit bone indices** in the skin index stream; import warns above 255 bones.
- **Animated non-joint nodes** (Armature motion) are treated as static; only
  joint curves are sampled.
- **One player per manager.** A manager is one character; give each character
  its own manager (they can share a `SkeletonAsset` once caching is added).
- **Blend shapes** are not carried in the neutral clip format yet.
- **Graphs, IK and humanoid retargeting** exist in Prowl.Motion but are not
  exposed as components yet; they can be added behind the same interfaces.
